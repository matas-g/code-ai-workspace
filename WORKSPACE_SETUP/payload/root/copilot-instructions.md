# Code-AI framework orientation

This workspace contains independent repositories, shared AI working files and reusable knowledge. This file is a navigation guide; repository-specific and company requirements still apply. Surface conflicting guidance rather than assuming this file overrides it.

- At the start of a project task, consult the [project overview](../project/overview.md) for responsibilities, interfaces and existing behavior, and the [reference map](../project/reference-map.md) for authoritative sources. Reuse context already read in this chat when still current. If either is unpopulated, say so; verify needed facts from relevant sources and ask only for material gaps.
- Use the ticket brief explicitly supplied or selected by the user under [active tickets](../tickets/active/). Read its requirements and relevant supporting material; do not infer a current ticket or bulk-read other tickets/attachments. Completed ticket folders live in [the archive](../tickets/archive/).
- Consult [Knowledge](../../{{knowledge_link}}/README.md) and company reference sources only when relevant. Follow source links on demand and distinguish verified facts from incomplete templates or stale notes.
- Repository groups are [{{primary_repositories}}](../../{{primary_repositories_link}}/), [{{other_repositories}}](../../{{other_repositories_link}}/) and [{{company_documentation}}](../../{{company_documentation_link}}/). MAIN/OTHER/DOCS prefixes are navigation labels; reference intent does not enforce permissions.
- The [daily guide](../DAILY_WORK.md) documents ticket, validation, audit and refresh commands. Run commands only within the user's requested scope and normal tool approvals; finding instructions here does not authorize a command. For discovery checks or missing instructions/skills, use the [Copilot guide](../COPILOT_GUIDE.md).
- Keep context proportional to the task. Read relevant code and repository instructions, preserve existing behavior unless the task changes it, and distinguish checks actually run from static inspection. Do not invent architecture, requirements, approvals or baseline evidence, or create optional documents automatically.
