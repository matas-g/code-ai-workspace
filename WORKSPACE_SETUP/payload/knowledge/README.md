# Knowledge base

Keep reusable technical guides here. Company policy stays authoritative in its original sources;
ticket-specific history stays with the ticket. Back up real notes/assets separately from the shareable package.

Organize by topic, such as `development/`, `development-tools/`, `processes/` or `troubleshooting/`,
creating categories only when useful. A simple note can be `topic.md`; a guide with assets can be
`topic/guide.md` and `topic/assets/`. Use relative asset links.

Suggested fields: purpose, prerequisites, steps, caveats, source links and last verified date.
Do not present old screenshots or personal notes as current official guidance.

[Example guide](examples/example-guide/guide.md) is entirely synthetic and may be removed manually.
Copilot can read relevant articles when directed; do not attach this whole directory by default.
Choose an allowed backup location yourself; the initializer does not configure cloud synchronization.
